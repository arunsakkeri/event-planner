Building this site

Picking the idea

My theme was Event Planner. I thought about what a planner actually needs day to day: a list of events, a fast way to change them, and a view of budgets and attendance.

Laying out the pages

I sketched four pages and kept the navigation identical on each one. A small script builds the menu and footer so every page stays in sync and I only edit it in one place.

Making CRUD work

The Manage Events page mocks create, read, update and delete. Events are held in browser local storage, so edits stick when you move between pages. Search, status filtering and form validation are built in.

Adding the charts

The analytics page reads the same event list and draws four Chart.js charts. Add an event on the manage page and the charts update.

What was tricky

Keeping all pages reading one data source. I pulled the storage logic into a shared file so nothing drifts. If I took this further I would swap local storage for a real database and add user accounts.
